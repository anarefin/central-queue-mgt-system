# Traceability matrix

SRS §27.1: every requirement ID maps to at least one automated test or documented UAT step, and a requirement with no
test is treated as not implemented. Covers tickets 01–19; later tickets append rows.

**Test types:** unit, integration (real PostgreSQL through Testcontainers, or a full Spring context), E2E, UAT, load,
manual. **Status:** `passing` (the test ran green in the last full run), `partial` (only part of the requirement is
covered, the gap is named), `manual` (verified by hand, steps given), `configured` (wired into CI but not yet run there),
`deferred` (belongs to a later ticket).

Paths: `B` = `backend/src/test/java/com/qms`, `F` = `frontend`.

**Notes on this ticket's interpretation.** The realtime `ticket.called`/`ticket.reannounced` event (`TicketEvents`,

**Notes on this ticket's interpretation.** The remote-share cap (FR-MOB-011) is read as bounding the share of the
queue remote tickets may already hold, not a share that blocks the very first remote join of an otherwise empty
queue (a literal `remote/(total+1) <= cap` reading would make the very first remote joiner of the day always refused

a place before arriving"): `IssuanceGate#forRemoteJoin` refuses only once `total > 0` and the *existing* remote share
