Devices fleet and the realtime channel

Pairing, fleet health, pushing commands and revoking a device; then the WebSocket hub: subscribe, heartbeat, reauth, replay after a gap and the close codes.

Devices fleet (/admin/devices/, config:org_sites_zones)

Pairing is a two-step handoff, never a shared secret typed into the device. The admin creates a code for a kiosk (scoped to a Site) or a display (scoped to a Zone): 8 characters from ABCDEFGHJKMNPQRSTUVWXYZ23456789 (no 0/O, 1/I/L), valid 10 minutes, redeemable once. The device exchanges it for its own credential: a short-lived access token (memory only) and a refresh token stored in the device (90 days), rotated on every refresh, hashed at rest, revocable on its own.

The fleet list shows each device with its Site or Zone, last seen, app version and a computed connectivity:

StatusRule
onlineheartbeat within the last 2.5 minutes
stalebetween 2.5 and 10 minutes
offlinebeyond 10 minutes, or never seen

Devices heartbeat every 60 seconds. Revoke ends the credential at once and drops the socket. Push reload and push config update send a live command over the device's own device:{id} topic. Printer paper status is Phase 2 and not tracked (the dashboard says so).

Realtime channel

Displays, consoles, dashboards and the visitor page subscribe to topics over WebSocket at wss://<host>/api/v1/stream, authenticated with the same bearer token as REST. Polling is only a fallback (5 s for displays, 15 s for mobile).

TopicSubscriber
queue:{service_id}Console, dashboard
zone:{zone_id}Display
counter:{counter_id}Console
ticket:{ticket_id}visitor page, kiosk confirmation
site:{site_id}:dashboardDashboard
site:{site_id}:alertsTeam and org admin
device:{device_id}Any device

Frames the client sends: subscribe {topics}, unsubscribe {topics}, heartbeat, reauth {token}. The server replies with one snapshot per topic, then event frames, each with a monotonic per-topic seq. Errors are {"frame":"error","code":"invalid_frame"|"unauthorized"}; a refused topic gets a denied frame.

RuleValue
Heartbeatevery 20 s each way; the server closes after 3 missed intervals (60 s)
Token expirysend reauth with a fresh token before exp; otherwise the server closes
Replay bufferat least 5 minutes or 1 000 events per topic; beyond it a fresh snapshot with "resync": true
Idempotencyapplying the same seq twice is a no-op; an announcement is de-duplicated by ticket_id + announce_count
Authorisationchecked per topic at subscribe and again on reauth

Close codes: 4401 token expired without a successful reauth, 4403 principal changed (user disabled, roles or scopes changed, device revoked), 4408 heartbeat timeout, 1001 server going away.

Testers cannot easily speak WebSocket by hand. Use websocat or the browser DevTools *Network > WS* panel, and lean on the named integration tests for the exact frame checks.
