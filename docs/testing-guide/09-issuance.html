Issuance: reception, kiosk, host API and the issuance gate

Every way a Ticket is created, every reason the gate can refuse it, idempotency, duplicate policy and rate limits.

Channels

ChannelWhoEntry pointTicket origin_channel
Receptionreception_operatorAdmin > Reception deskreception
Kioskpublic, paired device/kiosk/kiosk
Appointment check-inreception or kiosk deviceAPI only in this build (no screen)appointment_checkin
Mobile (remote join)registered visitor/visitor/join/?service=<id>mobile
Host APIa host application (host_system)POST /host/ticketsmobile (there is no host channel)

All of them pass through one gate (IssuanceGate) so the rules are identical. A refusal is 409 with a code and a details.reason, 429, or 503. The ticket is always created by the API before it is printed (FR-ISS-016), so a printer failure never loses a Ticket.

The issuance gate, in order

  1. Maintenance mode (503 unavailable, maintenance) - queued tickets keep being served.
  2. Rate limit (429, rate_limited) - a device 30 per minute, a visitor 5 per hour by default; staff and system actors are not limited.
  3. Service state (service_inactive), channel (channel_not_allowed), appointment-only (appointment_only).
  4. Opening hours (outside_hours), holiday (holiday), channel cut-off (past_cutoff), daily cap (cap_reached) - all 409 service_closed.
  5. Agent rostered (no_agent_rostered) when the Service demands one.
  6. Duplicate policy (duplicate_ticket).
  7. Remote-only checks: see Mobile visitor.

These rules have no Admin screen in this build. Set them with the endpoints below (curl) and read them back with GET. The Reception desk and kiosk simply obey them.

Holidays (full or half day)POST /sites/{id}/holidaysname at most 100, half day needs close_time

Kiosk (/kiosk/)

Public, unauthenticated device, paired with a code. Flow: idle > language > Service group (skipped if only one) > Service > *Identify yourself* (per the Service's visitor_identifier) > optional named agent > optional custom fifth level > Confirm > printing > result with the token, and a QR fallback when printing fails. Any inactivity returns to idle and discards the partial selection. High-contrast and large-text toggles persist in the browser.
