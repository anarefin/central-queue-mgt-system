Visitors: directory, registration, CSV import and privacy

Finding a known visitor, registering a walk-in, importing visitor master data, and the privacy controls that decide what is captured and shown.

Directory and registration (Reception desk)

Reception can find a known visitor (GET /visitors/lookup, visitor_pii:view) by pass code, phone number or a scanned QR value, then issue a Ticket for them. An unknown walk-in is registered (POST /visitors, ticket:issue): name and phone are required; email, category and purpose are optional and controlled by qms.visitor.registration-fields and the privacy capture surface. The response carries a pass reference V- plus 8 letters or digits (for example V-7K3M9PQR) that becomes their code next time.

The directory is a seam (VisitorDirectory); this release ships the local table. A directory that is slow (over qms.visitor.directory-timeout, default 1.5 s) or fails is abandoned and the next one tried; issuing a Ticket never calls the directory, it only takes a visitor_id Reception already resolved.

CSV import (/admin/visitor-import/)

A single admin-set column mapping maps CSV headers to visitor fields; external_code and name are mandatory, phone, email, category optional. Default mapping: external_code, name, phone, email, category. Manual upload runs at once and returns a report (rows seen, created, updated, and every skipped row by line number). Re-importing the same external_code updates in place, never duplicates. Scheduled pickup takes any *.csv from qms.visitor.import.pickup-dir on qms.visitor.import.pickup-cron (off by default) and moves it into processed/ or failed/. Every run stays on record.

A sample file for testing:

external_code,name,phone,email,category
T-0001,Aminul Islam,01700000001,aminul@example.com,Retail
T-0002,Rina Akter,01700000002,rina@example.com,Priority
T-0003,,01700000003,,Retail
,No Code,01700000004,,Retail

Privacy controls (/admin/privacy/)

Two runtime-toggleable closed, server-enforced field sets: capture (which of email, category, purpose a walk-in registration keeps) and kiosk_confirmation (whether the kiosk confirmation screen shows name and/or category). A field left off is not read from the request nor stored. A per-Site clinical sensitivity flag makes displays and announcements show a neutral label instead of the visitor's details. Export and anonymise are an Org Admin's own data-subject actions on one visitor; anonymise is irreversible.
