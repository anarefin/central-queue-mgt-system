Auth, users, roles and approvals

Sign-in, lockout, password policy, token refresh and revocation, idle timeout, user administration and maker-checker approvals.

How sign-in works

  • Staff sign in at /admin/login/ (administrators) or /console/login/ (agents). The access token (15 minutes, signed ES256) is kept in memory only. The refresh token is an opaque, hashed, single-use rotating value in an HttpOnly, SameSite=Strict cookie named qms_refresh (Secure unless you set QMS_REFRESH_COOKIE_SECURE=false).
  • The app refreshes silently. Idle timeout is refresh-token inactivity: 30 minutes for administrators, 12 hours for agents and reception.
  • Lockout: 5 failed attempts lock the account for 15 minutes (qms.security.lockout.*).
  • A wrong username and a wrong password give the same answer, so a username cannot be probed.

Settings that change these are in Appendix C.

Users, roles and approvals

Users are created and edited through the API (there is no Users screen yet). A user holds one or more role assignments, each optionally scoped to site_ids and group_ids. Scope travels as token claims. Disabling a user closes their open session, returns their bound tickets to waiting at the queue front, invalidates their refresh tokens and drops their sockets (principal.changed); REST read access can linger at most until the 15-minute access token expires (API-013).
