Industry walkthroughs: a day in the life

One narrative per shipped profile with numbered checkpoints. Each checkpoint links to the test case that proves it, so a business user can follow the story and tick the cases as they go.

How to use a walkthrough

Read the story, do what it says with the test users from Getting started, and stop at each Checkpoint. A checkpoint says what you should see and links the numbered case(s) that carry the exact steps and the Pass or Fail box. A walkthrough is a smoke test of a whole day. It is not a substitute for the case catalogue, which covers refusals and edge cases.

Every walkthrough starts from a fresh installation, applies its profile with Reset to this profile, creates one Site T-<date> with one Zone and three Counters, seeds the starter catalogue, links the Counters and creates a Reception, two agents and a Team Admin. Words in *italics* are the profile's own terminology.

1. Banking: a branch on a busy Monday

Profile banking: *Customer*, *Officer*, *Counter*, *Segment*. Appointments and remote join are on; journeys are off. Services: Cash deposit (A), Cash withdrawal (B), Account opening (C), Loan enquiry (D), Card services (E), Remittance (F). Classes: Priority banking (15), Senior citizen (10), Differently abled (10).

  1. Before opening. The Org Admin applies the profile and seeds the catalogue. Checkpoint 1: TC-PRF-001 and TC-PRF-002.
  2. Opening. Officer 1 opens a session on Counter 1 for Cash deposit and Cash withdrawal. Checkpoint 2: TC-SES-001.
  3. First customer at the kiosk. An anonymous customer taps *Tap to begin*, chooses Cash deposit and gets A-001. Checkpoint 3: TC-ISS-027. The display shows nothing yet.
  4. The Officer calls, serves and completes. F2, wait for *In service*, F5 with an outcome. Checkpoint 4: TC-SES-011, TC-SES-014, TC-SES-016. The display announced A-001 in English and Bangla with Western digits: TC-DSP-022.
  5. A senior citizen walks in behind three normal customers. Reception issues the ticket and sets *Senior citizen* (head start 10). Checkpoint 5: TC-ISS-002 and TC-QUE-001.
  6. The branch manager escalates. A *Priority banking* customer has arrived; the Team Admin changes an existing waiting ticket's class from the dashboard. Within 5 seconds every screen reorders. Checkpoint 6: TC-QUE-016 and TC-MON-007.
  7. A customer does not answer the call. The Officer presses F3 once, then F6. Checkpoint 7: TC-SES-021 and TC-SES-024.
  8. A transfer. A deposit customer needs a remittance. F7 to Remittance with the note *Needs remittance desk*. The customer keeps token A-006. Checkpoint 8: TC-SES-043.
  9. An appointment for a loan enquiry is booked at Reception for tomorrow. Checkpoint 9: TC-APT-013. Check-in has no screen (use the API): TC-APT-029.
  10. A customer joins from home. Card services, remote join from the phone, refused when too far. Checkpoint 10: TC-MOB-015 and TC-MOB-021.
  11. The Officer takes lunch. F9 with a *Lunch* break type. Checkpoint 11: TC-SES-053.
  12. Closing time. The Officer closes the session. The Org Admin exports the day. Checkpoint 12: TC-SES-006, TC-RPT-013, and the audit trail: TC-AUD-001.

2. Healthcare: an outpatient clinic

Profile healthcare: *Patient*, *Doctor*, *Consultation room*, *Department*, *Visit type*. Appointments and journeys are on; remote join is off; patient names are never announced. Services: Registration (A), Consultation (B), Sample collection (C), Pharmacy (D), Billing (E), Report collection (F). Classes: Emergency (30), Elderly (10), Pregnancy (10), Follow-up (5).

  1. Set up. Apply the profile; turn the journey setting on (API); create the template *Registration, Consultation, Sample, Pharmacy* (ordered). Checkpoint 1: TC-PRF-006, TC-JRN-001, TC-JRN-002.
  2. The display hides service names. Pair a display and set columns to Token and Counter only. Checkpoint 2: TC-DSP-003.
  3. Terminology. Every screen says *Patient* and *Consultation room*. Checkpoint 3: TC-PRF-009.
  4. A new patient. Reception issues the ordered journey. Only *Registration* has a ticket. Checkpoint 4: TC-JRN-003.
  5. Registration completes. The next stop's ticket appears by itself with the same class. Checkpoint 5: TC-JRN-004.
  6. An emergency. Reception issues with class *Emergency* (head start 30) and it is called ahead of people who arrived up to half an hour earlier. Checkpoint 6: TC-ISS-002 and TC-QUE-001.
  7. No name is announced. Call a named patient; the announcement contains only the token and room. Checkpoint 7: TC-DSP-027 and TC-DSP-028.
  8. A patient is held while waiting for a lab result. F8, call the next patient, then Resume. Checkpoint 8: TC-SES-038.
  9. A mobile patient cannot remote-join. The join page says the feature is off. Checkpoint 9: TC-MOB-019.
  10. A follow-up appointment is booked. Checkpoint 10: TC-APT-013.
  11. Doctor absent. The call times out and the Doctor returns the ticket. Checkpoint 11: TC-SES-029.
  12. Evening. Force-close a stale session left by a doctor who went home. Checkpoint 12: TC-SES-064.

3. Producer services: a supplier help centre with two buildings

Profile producer_services: *Producer*, *Officer*, *Desk*, *Producer code*, *Producer category*. Journeys, multi-site and visitor-code lookup are on; appointments are off. Services: Helpdesk query (A), Sample (B), Order and costing (C), Pre-QC (D), Voucher (E), Documentation (F). Classes: Distant-district producer (20), Scheduled visit (10).

  1. Set up. Apply the profile, create two Zones (*Building 1*, *Building 2*) at one Site and put Desks in both. Checkpoint 1: TC-PRF-011, TC-PRF-012.
  2. Import the producer master list from a CSV. Checkpoint 2: TC-VIS-009 and TC-VIS-011.
  3. A producer arrives with their code. Reception looks the producer up by code. Checkpoint 3: TC-VIS-003.
  4. One visit, three departments. An unordered journey over Sample, Pre-QC and Documentation issues three tickets at once in one Visit. Checkpoint 4: TC-JRN-005.
  5. The producer is called at Building 2, and their other tickets pause. Checkpoint 5: TC-JRN-007 and TC-JRN-008.
  6. Distant-district producer. A producer from far away is served ahead of locals who arrived less than 20 minutes earlier. Checkpoint 6: TC-PRF-015.
  7. An intra-site transfer across buildings. Transfer from Helpdesk to Order and costing in Building 2. Checkpoint 7: TC-SES-043.
  8. Appointments are off. Reception's appointment section is missing and the API refuses. Checkpoint 8: TC-PRF-026.
  9. Reports. The journey report shows one visit, three tickets and per-stop waits. Checkpoint 9: TC-RPT-009.

4. Government: a licensing office

Profile government: *Applicant*, *Reference number*, *Officer*, *Counter*. Appointments on; remote join, journeys and multi-site off. Services: Application submission (A), Verification (B), Payment (C), Collection (D). Classes: Senior citizen (10), Differently abled (10). There is no automated scenario for this profile: this walkthrough is the only end-to-end check.

  1. Set up. Apply the profile and seed. Checkpoint 1: TC-PRF-016.
  2. Mandatory reference number at the kiosk. Make Application submission require identification; the applicant must give a reference number. Checkpoint 2: TC-ISS-030.
  3. An applicant is served across four counters by transfer, not by journey. After submission, F7 to Verification, then Payment, then Collection; the applicant keeps one token number throughout. Checkpoint 3: TC-SES-043 and TC-SES-052.
  4. A journey is refused here. Checkpoint 4: TC-PRF-028.
  5. An appointment for verification. Checkpoint 5: TC-APT-013.
  6. Remote join is not offered. Checkpoint 6: TC-MOB-019.
  7. A notice on the lobby display about a holiday closure. Checkpoint 7: TC-DSP-016 and TC-ISS-011.
  8. Daily reset. The sequence restarts the next morning. Checkpoint 8: TC-CAT-021 (integration only).

5. Generic adapted into a telecom service centre (configuration only)

Follow the worked example in Industry configuration and then this day.

  1. Everything is configuration. Checkpoint 1: TC-PRF-046.
  2. A walk-in pays a bill at the kiosk and is called at Bay 1. Checkpoint 2: TC-ISS-027, TC-SES-011.
  3. An enterprise customer is called before ordinary customers who arrived less than 15 minutes earlier. Checkpoint 3: TC-PRF-048.
  4. A feature left off stays off. Journeys are refused. Checkpoint 4: TC-PRF-047.
  5. Device repair drop-off by appointment, remote-join for SIM replacement. Checkpoint 5: TC-APT-013, TC-MOB-015.
  6. End of day. Export the day and review the audit log. Checkpoint 6: TC-RPT-013, TC-AUD-003.
