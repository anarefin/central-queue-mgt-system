Audit log

What is recorded, how to search and export it, and the proof that nobody can edit or delete an entry.

What the audit log is

Every privileged action and every security outcome writes one append-only entry: who (actor and role), source address and device, when, the entity changed, before and after values and the reason. The application has no path that edits or deletes an entry, and the database refuses it. Passwords, tokens and OTPs are never stored.

Read it at GET /audit (JSON) or GET /audit?format=csv. There is no Admin screen; the *Reports > audit* domain report and the API are the readers. Permission: audit:read, System and Org Admin only.

ParameterMeaning
actor_identries by one user
actionexact (user.created) or a prefix ending in * (auth.*)
entity, entity_idthe record acted on
from, toISO date-time range
limit50 to 200 rows a page (next_cursor returned)
cursorthe cursor from the last page
format=csvexport; itself audited as audit.exported

The catalogue of action names is in Appendix F. A few you will look for while testing: auth.login.succeeded, auth.login.failed, auth.lockout, auth.refresh.reuse_detected, user.created, user.disabled, session.force_closed, ticket.transferred, ticket.priority_changed, feature_flag.updated, label.updated, profile.applied, report.exported, webhook_endpoint.created.
