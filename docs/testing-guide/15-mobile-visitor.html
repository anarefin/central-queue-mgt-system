Mobile visitor: ticket page, OTP login, remote join, arrival, feedback and web push

The phone experience: following a Ticket, signing in with an email code, joining a queue remotely and every reason that is refused, arriving or forfeiting, delaying, cancelling and giving feedback.

What the visitor app is

A mobile-first web app (a PWA) at /visitor/. There are no native apps in Phase 1 and no SMS (ADR-0011). Three entry routes:

RouteWhoPurpose
/visitor/?t=<ticketId>#s=<secret>anyone holding the Ticket link or QRlive status of one Ticket, cancel, feedback, push opt-in
/visitor/account/registered visitor (email OTP)active Tickets, appointment history, saved Sites, reschedule and cancel
/visitor/join/?service=<serviceId>registered visitorremote join of a Service's queue

The ticket secret rides the URL fragment (#s=), which the browser never sends to a server, and the page strips it with history.replaceState at once. It is never a query string and the page sends referrer: no-referrer. A missing or wrong secret and an unknown Ticket id both answer 401 unauthenticated, so a guess cannot tell them apart (FR-SEC-033).

Every visible noun (Customer, Patient, Token...) follows the active profile's terminology. Token digits are always Western Arabic.

Set-up for these cases

  • A working mailbox. The OTP is emailed. Run a mail catcher (for example Mailpit on port 1025) and set QMS_NOTIFICATION_EMAIL_HOST, _PORT, _STARTTLS=false in your compose override. Without SMTP the request is refused 503 unavailable (smtp_not_configured).
  • Remote-join rules per Service (API only today, no admin screen): PUT /services/{id}/remote-rule {"virtual_queue_enabled":true,"max_distance_m":5000,"max_remote_share_pct":50,"join_window_minutes":60,"arrival_deadline_minutes":30} and the Site's geofence centre PUT /sites/{siteId}/location {"latitude":23.78,"longitude":90.41}.
  • Delay and forfeit policy are database columns only. service_remote_rule.delay_allowed (default false) and .forfeit_policy (move_back default, or cancel) have no API and no screen today. To test them set them in SQL: docker compose -f deploy/compose.yaml exec postgres psql -U qms -d qms -c "UPDATE service_remote_rule SET delay_allowed = true, forfeit_policy = 'cancel' WHERE service_id = '<id>'". Recorded in Appendix E.
  • The virtual_queue feature flag must be on (Banking ships it on).

Sign in with an email code (OTP)

POST /auth/visitor/otp/request {email} emails a 6-digit code valid 10 minutes; POST /auth/visitor/otp/verify {email, code} signs in. At most 5 codes per email per hour and 5 wrong attempts per code by default. Sessions last 30 days by refresh token. Requesting a code for an unknown email creates the visitor.

Remote join and every refusal

A signed-in visitor opens /visitor/join/?service=<id>, allows their location, and joins. The Ticket is created with origin_channel: mobile and state remote: it accrues wait like any Ticket but cannot be called until it is checked in. POST /remote-join/{serviceId} needs an Idempotency-Key, latitude and longitude, and passes through the full issuance gate plus the checks below. GET /remote-join/{serviceId} previews without joining.

Remote-only checks, in order: flag virtual_queue (feature_disabled) > the Service's remote rule (virtual_queue_disabled) > uplink (internet_unreachable) > window (too_early) > location configured (site_location_unset) > distance (too_far) > share (remote_share_full).

Arrival, delay and forfeit

A remote Ticket becomes waiting when checked in within the arrival window: by scanning the site's own QR (?checkin=qr, which is itself the proof of presence, no location prompt), by geofence (location within the Site's radius), or by Reception (POST /tickets/{id}/reception-check-in). The visitor gets an approaching-turn alert when 3 Tickets or 15 minutes remain. If the arrival deadline passes the forfeit policy applies: cancel (state forfeited) or move_back (default, remote stays with a score penalty of 5 places).

Web push

Web Push (VAPID) is the visitor's phone channel. The public key is at GET /notification-config/web-push-key (no token); the page's opt-in registers a subscription POST /tickets/{id}/push-subscription. Push endpoints are SSRF-checked: only public HTTPS endpoints of a real push service are accepted. On iOS the page shows home-screen install guidance on the ticket page (not yet on the join screen).
