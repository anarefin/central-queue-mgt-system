B. Ticket state machine

Eleven states. remote, waiting, paused, called, serving and held are active; completed, transferred, no_show, cancelled and forfeited are terminal (shaded). Every transition writes exactly one ticket_event row with server time and device time and a per-ticket sequence number (Invariant 3). wait_seconds accumulates only in waiting and remote (Invariant 1). A ticket is bound to at most one counter session at a time (Invariant 2). transferred is terminal and the visit continues on a successor with the same token number (Invariant 4).

Notes. RETURN_FROM_SERVING and RETURN_FROM_HELD (with RETURN_FROM_CALLED) are the three ways a force-closed session or a disabled user returns its tickets to waiting at the front. MISS and RETURN_FROM_CALLED both return a called ticket to waiting; a miss counts, a call-timeout return does not. cancel() is out of band: allowed from any active state, by staff, or by the visitor while remote, waiting or paused. DELAY and FORFEIT_MOVED_BACK leave the ticket in remote. Appointments (held_slot, booked, rescheduled, checked_in, converted, cancelled, no_show) and counter sessions (open, on_break, closing, closed, force_closed) have their own machines in SRS 19.2 and 19.3.

E. Known limitations

Everything below was found while writing this guide, from the code, the traceability matrix (partial rows) and the ticket notes. Where two sources disagreed the code was believed. These are gaps in the product as built, not gaps in the guide.

Features that exist in the API but have no screen (run their cases with curl):

  • Users, roles and approvals (/users, /approvals), service accounts, the audit log reader, the config bundle, the break report.
  • Issuance rules: opening hours, holidays, channel cut-offs, daily cap, duplicate policy, require-agent, maintenance mode and the rate limits.
  • Remote-join rules and the Site geofence location (/services/{id}/remote-rule, /sites/{id}/location).
  • Appointment slot templates, exceptions and per-Service settings; staff appointment check-in, Reception check-in of a remote ticket, and staff reschedule or cancel of an appointment (only booking and availability have a Reception screen; the visitor can reschedule and cancel from /visitor/account/).
  • Journey templates and the journey-settings switch.
  • Zone voice settings (chime, volume, quiet period, announcement languages, queue depth) and per-language spoken forms of a token prefix.
  • Site quiet hours for notifications: the two columns exist but have no API or screen; set them in SQL.
  • Remote forfeit policy and delay allowed (service_remote_rule.forfeit_policy, .delay_allowed): database columns with no API and no screen, so the SRS's "configurable forfeit policy" cannot be set without SQL.
  • Business-hours version history and revert (API only; no hours page exists to attach it to).

Behaviour that is partial or unproven

  • Kiosk has no appointment check-in step (only the backend endpoint exists).
  • Password expiry only flags password_expired at sign-in; there is no forced-change screen (NFR-SEC-001).
  • No rendered-layout check for 40% string expansion; only lint bans fixed widths and truncation (FR-I18N-030).
  • Load test evidence: the k6 script is correct but no run summary survives in the repository, so the section 23.1 targets and 0.1% error rate are not independently evidenced (SRS 27.4).
  • Not producible by automation: 99.5% availability over a pilot month (NFR-AVL-001); console training to competence in 30 minutes (NFR-USA-005).
  • No real-device timing harness for idle-to-first-touch under 300 ms (NFR-PERF-007).
  • Diagnostics bundle omits application log lines (no in-process log buffer); use docker compose logs backend.
  • Application-layer encryption covers ticket.purpose_note only; visitor name, phone and email are deliberately not encrypted (NFR-SEC-011, see the matrix row for the reasoning).
  • Printer paper status is Phase 2 (FR-INT-051); the dashboard says *not tracked yet*.
  • WebSocket through the reverse proxy is configured from the nginx rules but was not exercised in CI.
  • iOS home-screen install guidance is on the ticket page but not on the join page (FR-MOB-020).
  • Team Admin and /admin/reports/: the sidebar shows Reports to a Team Admin but the page needs a Site read a Team Admin does not hold, so it does not work for that role.
  • Restore drill: a full pg_dump and pg_restore round trip was never run by the authors; run the drill in Operations.
  • Only three of five profiles have an automated Playwright scenario (Government and Generic have none).
  • Five of twelve UAT scenarios (U2, U3, U4, U7, U10) cannot be driven from a browser and are covered at integration level only.
  • Out of scope for Phase 1 by the SRS: SMS, native push, cross-site transfer (FR-QUE-054), the site edge node and offline site operation (FR-QUE-203/204, NFR-AVL-004), the Prometheus exporter half of NFR-MNT-003.
  • Test-suite flakes: hard-coded Monday dates in com.qms.appointment ITs are now in the past; an occasional resource-contention failure in SessionIT reruns green.
