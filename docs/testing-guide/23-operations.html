Operations: preflight, install, upgrade, backup and restore, diagnostics, health

Proving the installer refuses to half-install, an upgrade keeps every waiting ticket, a restore works and needs its key, and the support bundle is safe.

Where the procedures live

The full procedures are in docs/ops/ (installer.md, backup-restore.md, rollback-and-release-notes.md, tls-and-kiosk-display-shell.md, site-survey-checklist.md). This page gives the test cases for them. Several cases need a scratch machine: do not run backup, restore or upgrade drills on a live deployment.

AreaScript or endpointRequirement
Prerequisitesdeploy/preflight.sh (--skip-db on a first install)FR-OPS-001, FR-OPS-002
Offline bundledeploy/bundle.sh [file] then deploy/install.sh --bundle <file> (Windows: deploy/windows/install.ps1 -Bundle)NFR-POR-004
Migrationsdocker compose -f deploy/compose.yaml run --rm migrateFR-OPS-020
Backupdeploy/backup.sh --mode full and --mode wal-archive (QMS_BACKUP_KEY mandatory)FR-OPS-030
Restoredeploy/restore.sh --from <dir> --db-url ... --db-user ... --db-password ...FR-OPS-031

HealthGET /health/live, /health/ready, /health/dependenciesNFR-MNT-002

Kiosk lockdowndeploy/kiosk/launch-chromium-kiosk.shNFR-SEC-052

Targets: RPO at most 5 minutes (WAL archive with archive_timeout = 300), RTO at most 60 minutes.

TC-OPS-005

An upgrade never loses a waiting ticket or an open session

happy
SRS
FR-OPS-021, NFR-AVL-002, UAT
Role
operator, agent
Steps
  1. Have a waiting Ticket and an open session with a called Ticket.
  2. Follow the upgrade procedure: backup, load images, run migrate, restart backend.
  3. Reload the Console.
Expected

The session is still open, the called Ticket is unchanged, and F2 reaches the Ticket that was waiting before. Confirm GET /health/dependencies is up afterwards.

Dev / API
docker compose restart backend

TC-OPS-010

Restore into a fresh database (the acceptance drill)

happy
SRS
FR-OPS-031, NFR-AVL-003
Role
operator
Steps
  1. Take a full backup of a populated environment.
  2. Provision an empty database and migrate it.
  3. time deploy/restore.sh --from <backup> --db-url ... --db-user ... --db-password ....
  4. Compare row counts of site, ticket, users.
Expected

Elapsed time (RTO) is at most 60 minutes and printed by the script; the row counts match the source.

Dev / API
deploy/restore.sh --from ./backups/full-<ts>

Automated: manual. Note: a full pg_dump/pg_restore round trip was not run by the authors; run this drill before relying on it.

Pass Fail Notes
