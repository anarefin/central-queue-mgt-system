Aarong Central Queue Management, running

This guide walks through the pitch deck on the real system: start the stack, load the Aarong demo data, then follow a producer from the kiosk to the desk, the TV and the reports. Each step says what to do and what you should see. Allow about 45 minutes the first time.

      02

      Before you start

      You need a machine that can run this repository's Docker stack.

      1. Docker with Compose v2 (Docker Desktop or OrbStack on a Mac).
      2. curl and jq on the command line. On a Mac: brew install jq.
      3. A browser. To show a kiosk and a TV at the same time on one computer, you also need a second browser profile (see step 6).
      4. A terminal open at the root of the cqms repository. Every command below runs from there.

      The seed script applies the Producer services profile, which renames screen labels, turns on features and sets the branding. Don't run it against an installation you care about. The commands below start a separate stack called aarong-demo on port 8091, with its own database, next to anything already on port 8080.

      03

      Start the stack

      1. Set the demo stack's settings. The first administrator is created from these on the first start. 
        export QMS_DB_PASSWORD=aarongdemo
export QMS_HTTP_PORT=8091
export QMS_BOOTSTRAP_ADMIN_USERNAME=admin
export QMS_BOOTSTRAP_ADMIN_PASSWORD='Admin@2026'
export COMPOSE_PROJECT_NAME=aarong-demo
export BASE_URL=http://localhost:8091
      2. Build and start PostgreSQL, the backend and the web apps. The first build takes several minutes. 
        docker compose -f deploy/compose.yaml up -d --build --wait
      3. Check the backend is ready. 
        curl -s $BASE_URL/api/v1/health/ready

      {"status":"up"}, and localhost:8091/admin/ shows the Sign in page.

      If port 8091 is taken, pick another number for QMS_HTTP_PORT and BASE_URL. If the backend refuses to start, the bootstrap password was probably rejected by the password policy; choose a longer one and start again with a fresh database (see step 17).

      04

      Load the Aarong demo

      1. Run the seed script in the same terminal. It takes about a minute. 
        ./deploy/demo/aarong/seed.sh all

      A line for each part as it is created: the profile, the site and its 8 floors, the 19 departments with their desks, the users, 40 rows: 40 new for the producers, 8 phone bookings, about 5,600 historical tokens over 10 working days, and today's tokens being issued and served. It ends with the table of logins below.

      The script is safe to run again: it looks up what already exists and only adds what is missing. You can also run one part at a time, for example seed.sh live to open the desks again the next morning. seed.sh --help lists them.

      06

      Pair a kiosk and a TV

      Deck slides 18, 19: 3 kiosks and 9 TV monitors

      Kiosks and TVs are browsers that have been paired with the system once. A kiosk serves the whole site, so a producer can take a token for any building from any kiosk. A TV belongs to one floor and shows only that floor's desks.

      1. Print pairing codes for the 3 kiosks and 9 TVs, and keep the script waiting so it can set up each TV as soon as it is paired: 
        ./deploy/demo/aarong/seed.sh devices --wait
        Codes are valid for 10 minutes and each works once. Run the command again for fresh codes.
      2. In your main browser open localhost:8091/kiosk/, type the code for Kiosk CS-1 Lobby A into Pairing code and press Pair.
      3. In a second browser profile (or a different browser) open localhost:8091/display/ and pair it with the code for TV CS-1 5th floor.
      4. When the script prints newly paired and TV CS-1 5th floor, reload the TV page. Then press Ctrl-C to stop the script.

      The kiosk shows Welcome with a language choice (English, বাংলা). The TV shows a table of the 5th-floor desks with a notice board beside it.

      A browser profile remembers one paired device for the whole site. If you pair a TV in the same profile as the kiosk, it replaces the kiosk's pairing and both pages misbehave. Use a separate profile, a different browser, or a private window for each device.

      Without --wait, run ./deploy/demo/aarong/seed.sh displays after pairing TVs, then reload them. This applies the TV layout: serving table plus notice board, the next-token strip, and English and Bangla shown in turn.

      10

      Transfer, miss and take a break

      Deck slides 4, 23: no more walking between floors to queue again

      1. Transfer. Press F2 to call the next Design token, F4 to start, then F7 Transfer. Under Send to service choose Voucher (Finance, 3rd floor), write a note such as Sample approved, voucher needed, and press Transfer.
      2. Sign in to the console as finance.mahmud in a private window. The transferred producer is in Finance's queue with the same token number and the note.
      3. Miss. Call a token and press F6 when nobody comes. The token goes back into the queue to be called again; once it has been missed too often it closes as a no-show. F3 re-announces a call on the TV without counting a miss.

      17

      Finish, or start again

      1. Close the Officers' desks from their consoles with F10, or leave them open for the next demo.
      2. Stop the stack but keep the data: 
        docker compose -f deploy/compose.yaml stop
      3. Next morning, start it with up -d --wait and run ./deploy/demo/aarong/seed.sh live to open the desks and issue a fresh morning's tokens. Run seed.sh history as well to fill in the working days since the last run.
      4. Remove everything, including the database, and start from step 3 again: 
        docker compose -f deploy/compose.yaml down -v

      The ticket history is append-only by design, so individual tokens cannot be deleted. A fresh database is the only way to reset the demo. This only affects the aarong-demo stack as long as COMPOSE_PROJECT_NAME is set.

      Troubleshooting

      What you seeWhat to do
      cannot sign in as admin from the seed scriptExport QMS_BOOTSTRAP_ADMIN_USERNAME and QMS_BOOTSTRAP_ADMIN_PASSWORD as in step 3, or rely on aarong.admin after the first run.
      The pairing code is refusedIt expired after 10 minutes or was already used. Run seed.sh devices for new codes.
      Kiosk and TV both stop workingThey were paired in the same browser profile. Use a separate profile per device and pair again.
      The kiosk says it is outside opening hoursThe site was loaded with HOURS=realistic. Run seed.sh config without it.
      Reports are empty straight after loadingReports refresh every 15 seconds. Wait a moment and run the report again.
      The kiosk offers no Officer to pickOnly Officers with an open desk are offered. Run seed.sh live.
      seed.sh history cannot reach the databaseIt uses docker compose exec. Keep COMPOSE_PROJECT_NAME=aarong-demo set, or set PSQL to your own psql command.
